# Changelog

## Unreleased

### Changed
- **Delivery classification wired into `onboard` + the `GIT_STRATEGY` stub, org-parameterized (KJP-35).** The Stack interview (`onboard` ③) now asks two classification questions — **Q1** who controls deployment (*I control*: server/web/GitOps/self-host · *someone else*: store review / shipped client artifact) and **Q2** real-user SaaS? (Axis 2, "I control" bucket only) — and maps the answers to one of the three `DELIVERY_STRATEGY` buckets (**server-SaaS / server-personal / client**), recording the bucket in the project `GIT_STRATEGY` stub. `init` now seeds `GIT_STRATEGY.md` as a **pointer** to the common `DELIVERY_STRATEGY` policy (3 buckets + a "예외 없음 — DELIVERY_STRATEGY 준수" exceptions line) instead of a bare H1; the scaffold's skip-if-exists idempotency is unchanged. 🔴 **No git-flow value is hardcoded** — the org default is keyed by the brain-config `org` and lives in `DELIVERY_STRATEGY` §0 (`000_common/policies/`); `onboard`/`init`/`doc-catalog` **point** there and never restate it (restate → drift). The old "default is trunk-based" wording is dropped from `onboard` and `doc-catalog` for the same reason.
- **`GIT_STRATEGY` vs `DELIVERY_STRATEGY` naming disambiguated (KJP-29).** The `doc-catalog` GIT_STRATEGY row now pins the two as distinct artifacts: `GIT_STRATEGY` = per-project (`docs/tech-design/`, may carve exceptions) **points at** `DELIVERY_STRATEGY` = org-wide common policy (`000_common/policies/`, org default git flow, no project exceptions) — grounded on DELIVERY_STRATEGY §6.
- **`ss` now establishes `GOAL` before every recall (KJP-25).** The recall ranker hard-requires `GOAL` via a `${GOAL:?}` guard (`recall.md:18`, added in KJP-4), but `ss` only established `VAULT` — leaving the guard to fail loudly. `ss` now exports `GOAL` at **both** recall points, symmetric with `VAULT`: step 3 (resume, from the adopted session's `## Goal`) and step 6a (new, from the step-4 goal). Ticket named step 6a only; resume was fixed too since the guard fires there as well.

## 0.1.3 — 2026-07-23

### Changed
- **`DESIGN_SPEC` renamed to `DESIGN`, role expanded from link-holder to design-system spec (KJP-17).** Was: `DESIGN_SPEC` / kind `design-spec`, scoped to "holds Figma/Pencil links". Now `DESIGN` / kind `design` — an **FRD-grade design-system spec** (design tokens · component inventory · states · interaction rules) that **also** links the external SSOT (Figma/Pencil), not just links. Touches `doc-catalog` (row + kind), `vault-tree` (`DESIGN_SPEC.md` → `DESIGN.md` + annotation). Tier stays `situational` (UI products only). ⚠️ Canon only — the vault's existing `DESIGN_SPEC.md` files are renamed under KJP-24, not here.
- **`common/policies/` re-defined by binding force + scope, not origin (KJP-15).** The tier was described as *external* mandates — laws, regulations, certifications. It is now any norm that **binds every project in the vault**, origin-agnostic: an external mandate **or** a self-imposed org-wide invariant, gated on must vs. advice/technique. Touches `knowledge-convention` (3-axis table Content/Origin cells), `knowledge-escalate-convention` (§common/policies diagram + bullet), and `knowledge-promotion` (the obligation test in Step 2 and the sole-exception note in Step 1). The `Binding force = yes (no project exceptions)` cell was already on this axis and is unchanged.
- **ADR counterexample re-premised (KJP-15).** The "don't bundle decisions that may diverge per project" warning stands, but its test is now *whether an exception can arise inside this vault*, not *whether the org differs*. Consequently git branch strategy does **not** diverge in a single-org vault and stays in `common/policies/`; it would split per project only across distinct orgs sharing one vault.
- **Session commit is a per-vault choice, not a fixed gitignore (KJP-15).** The earlier session share-scope split stands — `sessions/` sits outside the team-shared surface; what changes is the premise that a gitignore was its *sole* implementation. The gitignore is now framed as the team-vault implementation only — a solo vault may track sessions (the commit doubles as backup). The plain-uid (never `[[wikilink]]`) rule for shared notes is unchanged, re-grounded on "a session may be absent from the shared surface." Touches `versioning-convention` §Share scope, `knowledge-promotion` reject-log clause, `knowledge-convention` `source_sessions` comment.
- **`ss` project-resolution wording tightened (KJP-15).** Step 2 said "infer from cwd"; it now reads "config `project:` first, then cwd", matching `project-inference.md` §Priority (config outranks cwd). Behavior unchanged — wording only.
- **recall grep priming now ranks deterministically with a hard cap (KJP-4).** The unranked "pick relevant + eyeballed 5–8" is replaced by a weighted-sum ranker (`10·section + 5·confidence + 4·overlap + 1·priority`, recency as strict tiebreaker) capped at `RECALL_N` (default 8). Shell/awk integer arithmetic, zero deps, deterministic per `(note, goal)`. Requires a `GOAL` env var (guarded — no silent failure). `confidence`/`priority` terms are forward-compatible (0 until the schema persists them).

### Added
- **`MILESTONE` document kind + new `docs/planning/` axis (KJP-17).** A roadmap document — **"when what"**: sequences already-defined scope across time. kind `milestone` · owner `pm` · tier `situational` · **not part of the 19-stub baseline** (created on trigger, like ADR/feature docs). Home is a new `docs/planning/` axis (a roadmap spans tech+business, so it sits above the tech/business split, not inside either). Boundaries pinned so it never duplicates neighbors: references PRD/FRD scope (never restates), links ADRs for the *why* (never records decisions), leaves fluid task/sprint status to the tracker (`docs/planning/` = durable plan). Touches `doc-catalog` (new group + boundary note), `vault-tree` (`docs/planning/MILESTONE.md` + naming example).
- **First body-template canon `doc-templates.md` (KJP-17).** Before this, only the frontmatter standard existed — no body-section templates. New file establishes the minimal skeleton (templates are copyable body skeletons living in this one canon file, not separate `.md`s; frontmatter is never repeated) and defines exactly two: `DESIGN` and `MILESTONE`. 🔴 Deliberately scoped to those two — the other ~22 kinds get **no** template, because a stub pre-filled with empty headings reads as false facts; a kind earns a template only when its body shape is stable. Restates the stub rule for templated docs (empty heading = "not yet written", flip to `draft` on first content). Linked from `project-docs-convention` header.
- **`kj-plugins` `docs/` tree decision reversed (KJP-17).** The 2026-07-16 decision to keep no `docs/` tree for this project is overturned (user, 2026-07-23) — the tree is created, but seeded with only what is needed now (MILESTONE), not all ~24 kinds as stubs. The vault-side creation (`013_kj-plugins/docs/`) and the `CLAUDE.local.md` Router line are PM follow-ups (vault write + shared-checkout config, both outside the plugin repo).
- **`update-over-create` names its tooling in canon (KJP-15).** `knowledge-convention` now states edit-existing-with-`Edit` / `Write`-only-for-new at the canon layer, so the scribe procedure's tool rule (`knowledge-promotion`) reads as canon-derived rather than a lone skill-level instruction.
- **Glossary anchoring in knowledge promotion (KJP-5).** The scribe promotion brief now attaches the existing-note title list (project `[K]` + common `[C]`) that recall's grep priming already emits, and instructs verbatim reuse for `title`/body/`related:` — guarding `related:` links against silent forks (`Cloudflare Tunnel`/`cf tunnel`/`CF Tunnel`). No new scan, no fuzzy/uuid layer.
- **Progress entry status-suffix convention (KJP-20).** `sessions-note-convention` now regulates the `### YYYY-MM-DD (suffix)` heading as a statusline contract: closed set `(parked)`/`(completed)`/none, one status token (round-count `#N` allowed after), vocabulary capped under 5, non-status descriptions barred from the suffix. Parser falls back to `active` on an unknown suffix. `sh`/`sc` carry canon pointers.

## 0.1.2 — 2026-07-18

### Added
- **`scripts/validate.sh` — schema checker (KJP-1).** Was: zero mechanical validation, every rule enforced by documentation discipline alone. Checks session uid shape + uid/filename agreement, the 3-value `status` vocabulary, required frontmatter keys, knowledge-note `title:`, and doc-status values leaking into sessions. Reports `file:line`, warns by default, `--strict` exits 1. bash 3.2, no dependencies beyond `awk`/`find` and coreutils. `scripts/validate-selftest.sh` covers it with 39 assertions; the suite is mutation-tested (16/16 mutants killed) because a passing assertion is not evidence that it can fail.
- **Human sign-off gate for `common/policies/` (KJP-2).** The normative axis — top of Document Conflict Precedence — no longer gets written by an agent. Candidates land on their normal tier and return as a `common-policy candidates` list, presented as one batch at `sh`/`sc`/dreaming §7. Agents draft; the user signs. Per-item interrupts are forbidden, and every other tier keeps the automatic score gate unchanged.
- **Third-time test (KJP-3).** dreaming §3's reject-log recurrence scan now states the rule it was implying: two occurrences make the third a rule. Detection and proposal only.

### Changed
- **`dreaming` §5 `project-policy candidates` renamed.** Both axes (org-wide `common/policies/` and per-project `docs/policy/`) surface approval-pending candidates in `## For PM` under near-identical wording — a signer could approve a project policy as an org-wide one. The two lists are now named apart and must never be merged.
- **`knowledge-promotion.md` reject-log clause** points at dreaming §3 as canon instead of describing the scan, which had made this file read as the spec.

### Notes
- Session `#### Mistake` recurrence was evaluated for inclusion in the third-time test and **deferred, not dropped**. The blind spot is real — a Mistake never mirrored into `Learned` escapes both the score gate and the reject-log — but sessions are an incremental scope and are records that carry no handled-marker, so recurrence there can neither be counted nor closed out. Record-format work has to land first (KJP-9). The reasoning is recorded in dreaming §3 so it is not rediscovered and re-attempted.

### Changed
- **ss resume: whole-file Read → awk section extract.** Resume injected the entire session file (worst case 94,948 B ≈ 31.6k tokens); it now extracts only `## Goal` + `## To-Do-List` + the newest Progress entry. Measured across 8 active sessions: 222,979 → 58,202 B (−74%).
- **Sessions split from the team share scope.** The shared surface is project trees (`NNN_*/`) + `000_common/`; `sessions/` is a gitignored personal episodic log. Shared notes reference sessions as plain uid text — never `[[wikilink]]` (dangles in teammates' vaults):
  - `versioning-convention`: new **Share scope** bullet (git canon)
  - `knowledge-convention`: wikilink ban noted on `source_sessions`
  - `knowledge-promotion`: `0.rejected.md` format `[[uid]]` → plain uid
  - `vault-tree`: `sessions/` annotated local-only
