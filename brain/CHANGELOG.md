Touches `sc` (④b), `dreaming` (§5 stub-scan), `worker`/`coder` (Risks line), `onboard` (③).
- **ADR creation wording aligned with scribe governance (KJP-22).** `project-docs-convention` §stub Pre-creation said "the `architecture` worker creates one", contradicting `memory-control-convention` ("Workers never write to the vault directly" — all vault writes are PM-delegated recording briefs). Credentials wording corrected: the old "CLAUDE.local.md holds ticket-system credentials" line misdescribed reality — `ticket-system` is an identifier only, and real credentials live in **neither** CLAUDE file (separate env, e.g. `~/.config/claude/huly.env`). Pre-split projects migrate by re-running init: each file's brain block is regenerated between its own `brain:begin/end` markers, so the shared sections leave `.local` in the normal idempotent rewrite (documented only — no project was migrated here). Touches `init` (step 2 split 2a/2b + step 3 "never gitignore CLAUDE.md"), `onboard` (prerequisite + ① ticket-system home), `project-inference` (`project:` read from `CLAUDE.md` first), `sessions-note-convention` (PM-role canon home), `README` (quickstart · ownership table · FAQ). vault-root/Router references in `ss`·`sh`·`sc`·`recall`·`knowledge-promotion`·`dreaming` stay pointed at `CLAUDE.local.md` — still its home. Follow-on consistency (verifier findings): `hooks/force-delegate.sh` whitelists the project-root `CLAUDE.md` (init 2a would otherwise be blocked where the hook is wired) and the "CLAUDE.md pointers" recall-layer shorthand in `memory-control-convention`·`dreaming` is renamed to **CLAUDE.local.md Router pointers** — post-split, the old name pointed at the committed file, the exact leak this split prevents.
- **Delivery classification wired into `onboard` + the `GIT_STRATEGY` stub, org-parameterized (KJP-35).** The Stack interview (`onboard` ③) now asks two classification questions — **Q1** who controls deployment (*I control*: server/web/GitOps/self-host · *someone else*: store review / shipped client artifact) and **Q2** real-user SaaS? (Axis 2, "I control" bucket only) — and maps the answers to one of the three `DELIVERY_STRATEGY` buckets (**server-SaaS / server-personal / client**), recording the bucket in the project `GIT_STRATEGY` stub. `init` now seeds `GIT_STRATEGY.md` as a **pointer** to the common `DELIVERY_STRATEGY` policy (3 buckets + a "예외 없음 — DELIVERY_STRATEGY 준수" exceptions line) instead of a bare H1; the scaffold's skip-if-exists idempotency is unchanged. 🔴 **No git-flow value is hardcoded** — the org default is keyed by the brain-config `org` and lives in `DELIVERY_STRATEGY` §0 (`000_common/policies/`); `onboard`/`init`/`doc-catalog` **point** there and never restate it (restate → drift). The old "default is trunk-based" wording is dropped from `onboard` and `doc-catalog` for the same reason.
- **`GIT_STRATEGY` vs `DELIVERY_STRATEGY` naming disambiguated (KJP-29).** The `doc-catalog` GIT_STRATEGY row now pins the two as distinct artifacts: `GIT_STRATEGY` = per-project (`docs/tech-design/`, may carve exceptions) **points at** `DELIVERY_STRATEGY` = org-wide common policy (`000_common/policies/`, org default git flow, no project exceptions) — grounded on DELIVERY_STRATEGY §6.
- **Knowledge promotion is now a two-gate judgment; every reject carries a coded reason (KJP-6).** The single score gate (sum ≥ 3) stays as **Gate 1** — deterministic, unchanged. A **Gate 2 similar-note verdict** now follows for every Gate-1 passer: scribe checks the item against the existing-note title list the brief already carries (KJP-5 glossary anchoring — recall's grep priming, run once and reused; no new scan, no vector search, no LLM gate) plus the update-over-create note Read, and returns exactly one of the closed enum **`promote / already_known / not_durable / unsupported`** — only `promote` writes. The `0.rejected.md` line gains a reason slot: `- <YYYY-MM-DD> · reuse/prevent/conf=a/b/c(=sum) · <reason> · "<verbatim>" · <uid>`; a Gate-1 below-bar line always carries `not_durable` (its real rationale is the score triple — `sum < 3` tells the gates apart, and the fixed code keeps one uniform machine-groupable format instead of two). Dreaming §3 now tallies the codes — **key diagnostic: recurring `already_known` = the note exists but recall failed to surface it → a retrieval defect, not a capture defect** (recall-fix signal: title/Trigger wording, missing `related:` links). Dedup discipline unchanged ("write roughly, Dreaming cleans up") — when torn, `promote` wins; `already_known` is for literally-nothing-to-add only. cognee-distill mapping: Gate 1 = the deterministic no-LLM gate, Gate 2 = the writer/rejecter with its rejection enum unextended (the curator between them = Dreaming, already in place). Touches `knowledge-promotion` (canon header · Why-separate · Steps 1·2 · format · returns), `knowledge-escalate-convention` (Stage-1 line), `dreaming` (§3 aggregation clause shared with KJP-8 + §6 Rejects row), `sh`/`sc` (gate wording), `README` (§Single-Source Map row).
- **`ss` now establishes `GOAL` before every recall (KJP-25).** The recall ranker hard-requires `GOAL` via a `${GOAL:?}` guard (`recall.md:18`, added in KJP-4), but `ss` only established `VAULT` — leaving the guard to fail loudly. `ss` now exports `GOAL` at **both** recall points, symmetric with `VAULT`: step 3 (resume, from the adopted session's `## Goal`) and step 6a (new, from the step-4 goal). Ticket named step 6a only; resume was fixed too since the guard fires there as well.

### Added
- **Knowledge notes gain a helpful/harmful feedback loop — `recalled:`/`useful:` counters wired from injection to ranking (KJP-7).** Promotion was one-way: nothing fed back whether recalled knowledge actually helped, and staleness was an after-the-fact flag. Two optional integer frontmatter fields close the loop (canon: `knowledge-convention` §Feedback counters): `recalled:` = sessions the note was injected into, `useful:` = sessions it actually helped; **absence = 0** — no backfill across pre-existing notes (vault measured 2026-07-25: 382 notes, 0 carrying either field). The session `## Context` recall block is declared the **canonical injected-notes record** (each line already carries its source path — `ss` step 6 / `recall.md` §Injection; no new section, no separate list; resume recall stays screen-only and counts nothing). `sh`/`sc` bump the counters inside their existing promotion delegation: PM extracts the injected list + designates the actually-used subset, scribe Edits `recalled:` +1 / `useful:` +1 (CAS on the literal value; absent → insert at 1), **once per session** via a counter-marker line in the recall block (later parks top-up `useful:` only); `[M]` session lines and `000_common/policies/` (signature tier) are never touched; counter-bumped paths join the commit pathspec. The ranker's **W_CONFIDENCE term now reads `useful:`** — `min(useful,10)*10`, replacing the never-persisted `score:` read; **weight structure unchanged** (S10/C5/O4/P1/rec0.5) — the C term was forward-compatible 0 until now. 🔴 **No automatic deletion from counters, ever** — a low `useful`/`recalled` ratio yields exactly ranking demotion (self-acting via the C term) + a Dreaming §1 rewrite·merge-candidate flag (proposal only). Touches `knowledge-convention` (fields + §Feedback counters), `recall` (conf source · ranker table · §Injection · marker), `ss` (6b canonical record · step-3 boundary), `sh`/`sc` (counter clause · Context marker bullet · pathspec), `dreaming` (§1 net-help flag), `README` (map row).
- **Dreaming §3 gains the session-Mistake recurrence scan — the 0.1.2 deferral is lifted by landing its two preconditions (KJP-9).** The deferral said "do not re-add this scan until that format change lands"; this change **is** that format change. Precondition 1 — the **dream-log gets its first format canon** (`dreaming` §7, grounded on the live file's measured shape): one date heading per run (newest at top = §0's baseline read), 🔴 a `<project>` field on every project-scoped item line (one vault-wide file — without it, keys from different projects cross-suppress), 🔴 cumulative whole-log read for every consumer beyond the baseline date (keys accumulate; the newest entry is not the state). Precondition 2 — knowledge notes gain **`source_items:`** (`knowledge-convention` §Item-level provenance): the verbatim Mistake/Learned line(s) a note restates, copied by scribe at promotion; pre-existing notes have none → **uid-level `source_sessions` fallback, with item-level suppression explicitly impossible** for them. The scan itself (canon: `dreaming` §3): combs `#### Mistake` blocks for the same mistake in **≥2 distinct sessions** (third-time-test precedent), detect·propose only — 🔴 session files are never marked (non-negotiable); close-out lives in dream-log suppression keys. Its six built-in guards: **(1)** §0 gains an explicit full-scan carve-out with the pollution-argument rebuttal (detect·propose only ⇒ no pollution surface; cost handled per-scan); **(2)** hard cap `DREAM_MISTAKE_N` (default 30, newest per project) bounds the O(N²) pairwise test (≤435 pairs) — the `RECALL_N` precedent; **(3)** machine boundary stated, not solved — sessions may be local-only while the log is shared, so counts are per-machine observations (never "correct" another machine's keys); **(4)** both recall [M] guards inherited (`session_type: dreaming` skip + per-`project:` bucketing, empty project skipped); **(5)** fuzzy/exact symmetry — one normalized-token-overlap test (≥0.6 vs the smaller set) for counting **and** suppression-key matching (exact-string close-out would resurrect paraphrases); **(6)** the recall.md [M] awk now terminates on `/^##/` instead of `/^####/` — a trailing Mistake block no longer swallows the next `### ` date entry / `## ` section (fixture-verified; minimal one-line diff to the KJP-4 pipe). Kept distinct from the KJP-8 tag count: machine string vs content similarity. Touches `dreaming` (§0 carve-out · §3 scan · §6 row · §7 format), `knowledge-convention` (`source_items`), `knowledge-promotion` (Step 2 source_items write), `recall` (awk fix), `README` (map rows).
- **Mistakes can name the skill step they happened in; dreaming aggregates them into skill-improvement proposals — and can never apply them (KJP-8).** Dreaming consolidated knowledge but never fed back into the skills themselves, so a procedure step could fail repeatedly with nothing accumulating. Session `#### Mistake` lines gain an **optional** inline tag `[skill:<skill>§<step>]` (at most one, end of line, step label exactly as the skill doc writes it; absent = not skill-tied — never guessed). Chosen over a frontmatter field because Mistakes are per-line items (a session field cannot attach to one mistake), and the bracket token follows the statusline-suffix precedent of machine-parsed inline notation — while staying off the Progress-suffix closed set. Dreaming §3 counts tags by **exact string** (full grep over `sessions/` — a machine-tag count needs no similarity judgment or handled-marker, so it is exempt from the KJP-9 content-recurrence deferral — since lifted by the KJP-9 entry above); **the same tag on ≥2 distinct sessions** (third-time-test precedent) produces a proposal section in `<vault>/000_common/skill-proposals.md` (runtime output written by scribe — not a repo file): current wording / proposed wording / evidence session uids (plain, no `[[ ]]`). Existing sections get a uid refresh, never a duplicate; `~`-marked sections are handled and skipped. 🔴 **No auto-apply path exists, by design** — the pipeline terminates at the proposal file; the user reads and applies by hand (the propose·approve principle applied to the harness's own procedures). The KJP-6 reason-code tally and this tag count land as **one** §3 structured-signal clause — the same move twice (free text → coded field → deterministic batch tally). Touches `sessions-note-convention` (Mistake tag), `dreaming` (§3 clause shared with KJP-6 · §3 deferral carve-out · §6 metrics row).

- **recall grep priming now ranks deterministically with a hard cap (KJP-4).** The unranked "pick relevant + eyeballed 5–8" is replaced by a weighted-sum ranker (`10·section + 5·confidence + 4·overlap + 1·priority`, recency as strict tiebreaker) capped at `RECALL_N` (default 8). Shell/awk integer arithmetic, zero deps, deterministic per `(note, goal)`. Requires a `GOAL` env var (guarded — no silent failure). `confidence`/`priority` terms are forward-compatible (0 until the schema persists them).

## 0.1.2 — 2026-07-18

### Added
- **`scripts/validate.sh` — schema checker (KJP-1).** Was: zero mechanical validation, every rule enforced by documentation discipline alone. Checks session uid shape + uid/filename agreement, the 3-value `status` vocabulary, required frontmatter keys, knowledge-note `title:`, and doc-status values leaking into sessions.
