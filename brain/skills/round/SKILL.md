# round — 병렬 트랙 라운드 운용

- PM 이 직접 실행한다. 트랙 실행만 워커에 위임하고, 판정·머지·라이브 쓰기는 PM 이 쥔다.
- 목표는 "동시에 많이"가 아니라 **CI 를 통짜로 죽이지 않고 끝내는 것**이다. 트랙 수는 교집합 실측 결과가 정하지, 카드 개수가 정하지 않는다.
- 전제 — 트렁크 기반 git(`main` 보호 + 단명 브랜치 + squash merge). 다른 전략이면 §7 머지 절만 프로젝트 규약으로 갈아끼운다.

## 왜 이 순서인가

라운드가 깨지는 지점은 셋뿐이고, 절차는 그 셋을 각각 막는다.

1. **교집합 오판** — 두 트랙이 같은 곳을 고쳐 두 번째 머지가 충돌하거나, 더 나쁘게는 조용히 통과한 뒤 CI 가 통짜로 red 가 된다. → §2
2. **스테일 수치** — 카드 본문의 행수·비율은 전부 작성 시점 스냅샷이다. 그걸 근거로 짠 브리프는 처음부터 틀린 일을 시킨다. → §3
3. **회수 실패** — 워커가 끝나도 PM 이 모른다. 워크트리 에이전트는 subagent 가 아니라 **독립 세션**이라 완료 알림 채널이 없다. → §4·§6

## 1. 후보 선정

- 티켓 시스템에서 카드 본문을 **직접** 읽는다. 제목만 보고 범위를 추정하지 마라 — 제목은 카드가 열릴 때의 가설이고, 본문에 그 뒤의 실측이 붙어 있다.
- 카드 본문이 다른 카드 번호를 참조하면 번호 체계가 이관된 적 있는지 확인한다(이관된 티켓은 본문 번호와 현재 번호가 어긋난다).
- 우선순위·크기·선행 관계로 후보를 추린다. 큰 축 하나를 열면 나머지가 그 하위로 흡수될 수 있으니, 부모 카드가 있으면 먼저 펼쳐 보고 판정한다.

## 2. 교집합 실측 — 라운드의 승패가 여기서 갈린다

**카드 본문이 아니라 코드를 grep 한다.** 카드에 적힌 파일 목록은 카드 작성 시점의 것이고, 그 사이 머지분으로 바뀐다.

세 층을 전부 본다. 파일 층만 보면 반드시 샌다.

| 층 | 무엇을 찾나 | 왜 |
|---|---|---|
| 파일 | 각 카드가 건드릴 파일 | 기본 |
| 라인 | 같은 파일 안에서 각 카드가 닿을 줄 범위 | 파일이 겹쳐도 라인이 떨어지면 병렬 가능 |
| 공유 자산 | 원장·레지스트리·인벤토리 문서·스냅샷 테스트 | **여기가 진짜 지뢰** |

공유 자산이 위험한 이유 — 그것은 어느 카드의 "점유 파일" 목록에도 안 적혀 있는데, 신규 참조·신규 폐기 컬럼·신규 심볼을 등록하라고 요구한다. 그래서 서로 무관해 보이는 두 카드가 같은 원장 테스트를 고치게 되고, 두 번째 머지에서야 발견된다.

- 판정 신호: 카드가 **폐기·이관·신규 참조**를 건드리면 공유 원장을 건드릴 가능성이 높다. 문서만 고치는 카드도 그 문서가 원장이면 해당된다.
- 라인 층까지 봤으면 **각 트랙이 소유한 줄 범위를 브리프에 숫자로 적는다.** 워커는 자기 범위 밖을 안 건드리고, 파일 전체 재포맷도 안 한다(재포맷 1회 = 타 트랙 충돌 확정).
- 겹치면 트랙을 합치지 말고 **순서를 준다** — 작은 쪽을 먼저 머지하고 큰 쪽이 리베이스한다.

## 3. 라이브 수치 재측정

- 카드에 박힌 행수·비율·분포는 전부 스냅샷이다. **실행 시점에 다시 센다.**
- 조회는 읽기 전용으로. 라이브 쓰기는 이 단계에서 절대 하지 않는다.
- 측정값은 브리프에 그대로 옮겨 적는다 — 워커가 다시 재는 왕복을 없애고, 카드와 실측이 다르면 그 차이를 브리프가 명시한다.
- 카드 수치와 실측이 어긋나면 그 자체가 보고거리다. 조용히 실측값만 쓰고 넘어가면 카드는 계속 낡은 채로 남는다.

## 4. 브리프 작성 — 트랙당 1장

고정 절 7개. 각 절이 없으면 워커가 그 자리를 추측으로 메운다.

```markdown
# 브리프 — <티켓> · <한 줄 제목>

## Goal
- 무엇을 끝내는지 1~2줄. 범위 밖도 명시("컬럼 폐기는 이 카드의 필수 범위가 아니다").

## 실측 (PM 이 <날짜> 직접 측정 — 카드 본문 수치는 스테일)
- §3 에서 잰 값을 그대로.

## 점유 파일 (이 브랜치가 건드려도 되는 곳)
- 경로 + 줄 범위.

## 🔴 병렬 트랙 충돌 회피
- 같은 파일에서 **타 트랙이 소유한 줄 범위**를 트랙 이름과 함께 명시.
- 파일 전체 재포맷·정렬·import 정리 금지.

## 제약
- 라이브 쓰기 금지(스크립트 작성까지만, 실행은 PM).
- 🔴 `pkill`/`killall` 금지 — 같은 머신에서 트랙 N개가 돈다. 패턴 매칭은 워크트리를 안 가린다.
- 공유 원장에 신규 항목을 등록해 CI 를 통과시키지 마라 — 픽스처를 프로덕션 경로로 바꾸는 것이 정답이다.
- push 금지 — push·PR·머지는 PM.

## DoD
- [ ] 체크박스. 검증 가능한 것만.

## 보고
- 🔴 **작업이 끝나면 SendMessage 로 PM 에 보고해라. 터미널에만 출력하면 PM 이 못 본다.**
- 보고 항목을 열거: diff --stat · 테스트 결과 · 실측 출력 · 판정이 필요한 열린 질문.
```

마지막 절이 오늘 가장 자주 빠지는 절이다. 워크트리 에이전트는 **독립 Claude 세션**이라 완료 알림이 PM 에게 자동으로 가지 않는다. 지시가 없으면 워커는 자기 터미널에 완벽한 보고서를 쓰고 조용히 끝난다.

## 5. 워크트리 기동

`scripts/spawn-track.sh` 를 쓴다. 스크립트가 존재하는 이유는 매번 같은 3개 함정을 밟기 때문이다:

- 워크트리 생성기가 **브랜치명을 워크트리명 그대로** 만든다 → `<type>/<name>` 으로 리네임해야 규약에 맞는다.
- 에이전트 지정 없이 만들면 터미널이 **빈 셸**로 남는다.
- gitignore 된 로컬 설정 파일(`CLAUDE.local.md` 등)이 **워크트리에 안 따라간다** → 본체로 심볼릭 링크.

```bash
brain/skills/round/scripts/spawn-track.sh <repo-selector> <TICKET-slug> <type> <브리프경로>
```

프로젝트의 워크트리 도구가 다르면 스크립트 대신 같은 3개 보정을 손으로 한다 — 보정 자체가 요점이지 도구가 요점이 아니다.

기동 후 티켓 상태를 진행 중으로 옮긴다.

## 6. 회수

- 워커가 보고를 보내오면 그 자리에서 처리한다. **판정 요청은 미루지 마라** — 워커는 대기 상태로 멈춰 있다.
- 워커가 조용하면 `ListAgents` 로 주소를 확인하고 `SendMessage` 로 상태를 물어라. 동시에 워크트리의 `git log`·`git status` 로 실제 진행을 직접 잰다 — 보고와 실물이 다를 수 있다.
- **보고를 그대로 믿지 않는다.** 머지 전에 PM 이 직접 확인할 것:
  - `git show --stat` 으로 닿은 파일이 브리프 범위 안인지
  - 워커가 인용한 근거(줄 번호 앵커, 실측 수치)가 실제로 그런지
  - 타 트랙 소유 줄에 diff 가 0인지
- 워커가 범위를 넘었다고 자진 보고하면(오늘 흔하다) 넘은 이유를 보고 판단한다 — 모순을 남기는 것보다 1줄 넘는 게 나은 경우가 많다.
- 워커가 남긴 열린 질문은 PM 이 답한다. 답할 때 **근거 1줄**을 같이 준다 — 워커가 그 근거를 커밋 메시지에 넣는다.

## 7. 순차 머지

- **작은 트랙부터.** 마지막에 가장 넓은 트랙이 남으면 그놈만 리베이스하면 된다.
- 한 번에 하나씩 — 머지 1건 = 배포 run 1건이고, run 이 병렬로 돌면 완료 역순일 때 구 SHA 가 새 SHA 를 덮는다.
- 각 머지 후 CI·배포 run 완료를 기다린다. run 상태 표시는 스테일할 수 있으니, 반영 확인은 **배포된 결과물을 직접 읽어** 한다.
- 앞선 머지가 끝나면 남은 트랙에 리베이스 신호를 보낸다. 신호에 **무엇이 바뀌었는지**(어느 파일 어느 줄) 같이 적어라 — 워커가 충돌을 내용 기준으로 풀 수 있다.
- 리베이스 시 **타 트랙이 넣은 게이트·assert 를 지우지 말라**고 못 박는다. 충돌 해소 중 가장 흔한 사고다.

## 8. 마감

- 카드를 완료로 옮기고, 카드에 실측값·판정 근거를 남긴다.
- 라이브 쓰기가 필요한 산출(백필 스크립트 등)은 **배포 후 PM 이 실행**한다. dry-run → 결과 확인 → apply 순서로.
- 후속으로 분리된 것은 새 카드로 만든다 — 분리 판정이 대화에만 남으면 다음 라운드에서 사라진다.
- 라운드에서 배운 것(교집합 오판 지점, 새 함정)은 세션 노트 `learned` 에 남긴다. 다음 라운드의 §2 가 그걸 읽는다.

## 금지

- 카드 개수에 맞춰 트랙 수를 정하는 것 — 트랙 수는 §2 가 정한다.
- 파일 층만 보고 "교집합 0" 판정 — 공유 원장을 안 본 판정은 판정이 아니다.
- 워커에 push 권한 위임 — 순차 머지가 무너진다.
- 워커 보고만 읽고 머지 — §6 검증 없이는 머지하지 않는다.
- 라이브 DB·운영 환경에 워커가 직접 쓰기 — 작성은 워커, 실행은 PM.
